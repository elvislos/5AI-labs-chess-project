Drie bugs in de voorbeeldcode die je moet kennen:

  • best_utility = 0 als startwaarde. Een zet wordt alleen gekozen als hij strikt beter dan 0 is. Zijn alle zetten 0 (de meeste zetten slaan niets), dan blijft de willekeurige zet staan. Daarom speelt hij zo random.
  • De tijdslimiet wordt alleen tussen zetten gecheckt. Een trage evaluatie kan de limiet ruim overschrijden.
  • constraints: dict = {} als default-argument is een gedeeld, muteerbaar object, een klassieke Python-valkuil.

03 · Minimax en negamax

Rekening houden met een tegenstander die terugvecht

Schaak voldoet aan de aannames van les 08: deterministisch, om beurten, twee spelers, zero-sum en perfect information. MAX (wit) kiest de zet met de hoogste waarde, MIN (zwart) die met de laagste. Een zet van één speler heet een ply.

def minimax(board, depth, maximizing):
    if depth == 0 or board.is_game_over():
        return evaluate(board)          # wit-perspectief
    if maximizing:
        return max(minimax_after(board, m, depth, False) for m in board.legal_moves)
    else:
        return min(minimax_after(board, m, depth, True) for m in board.legal_moves)

Complexiteit: tijd O(bm), ruimte O(bm). Bij schaak is de branching factor b ≈ 35. Diepte 4 betekent al 354 ≈ 1,5 miljoen bladeren.

Negamax: één functie in plaats van twee

Omdat het zero-sum is, geldt max(a, b) = −min(−a, −b). Laat de evaluatie altijd scoren vanuit de speler die aan zet is en draai het teken om bij elke ply:

def negamax(board, depth):
    if depth == 0 or board.is_game_over():
        return evaluate_side_to_move(board)
    best = -INF
    for move in board.legal_moves:
        board.push(move)
        best = max(best, -negamax(board, depth - 1))
        board.pop()
    return best

def evaluate_side_to_move(board):
    sign = 1 if board.turn == chess.WHITE else -1
    return sign * utility.board_value(board)   # Utility geeft wit-perspectief
Klassieke bugHet perspectief omkeren gebeurt op precies één plek. De Utility blijft wit-positief, zoals het framework voorschrijft. Doe je de omkering dubbel of niet, dan speelt je engine plots de slechtst mogelijke zetten voor één kleur.

Eindtoestanden scoren

  • Mat: de speler aan zet staat mat, dus return -MATE + ply (bv. MATE = 100 000). Door + ply verkiest de engine een snellere mat en stelt hij een verloren mat zo lang mogelijk uit.
  • Pat, onvoldoende materiaal, herhaling: return 0.
04 · Alpha-beta pruning

Hetzelfde antwoord als minimax, met een fractie van het werk

Alpha-beta houdt twee grenzen bij langs het huidige pad:

  • α (alpha): de beste waarde die MAX al zeker heeft. Denk "at least".
  • β (beta): de beste waarde die MIN al zeker heeft. Denk "at most".

Zodra α ≥ β kan deze tak de uiteindelijke beslissing niet meer beïnvloeden: één van beide spelers zal hier nooit naartoe gaan. De resterende kinderen worden overgeslagen. Dat heet een cutoff.

def negamax(board, depth, alpha, beta, ply=0):
    if board.is_checkmate():
        return -MATE + ply
    if board.is_stalemate() or board.is_insufficient_material() or board.is_repetition(2):
        return 0
    if depth == 0:
        return quiesce(board, alpha, beta)      # module 08
    best = -INF
    for move in ordered_moves(board):           # module 05
        board.push(move)
        score = -negamax(board, depth - 1, -beta, -alpha, ply + 1)
        board.pop()
        if score > best:
            best = score
        if score > alpha:
            alpha = score
        if alpha >= beta:
            break                               # beta-cutoff
    return best

Let op het venster (-beta, -alpha): bij negamax wisselen de grenzen van rol én teken bij elke ply.

▲ MAX-knoop▼ MIN-knoopDoorzichtig + gestreept = gesnoeid, nooit bekeken

05 · Zetvolgorde

Beste zetten eerst, want dan snoei je het meest

Alpha-beta snoeit pas als het snel een goede zet vindt. Een goedkope volgorde-heuristiek levert in de praktijk vaak meer winst op dan een slimmere evaluatie.

  1. Hash move / PV-move: de beste zet uit de vorige iteratie of uit de transposition table eerst.
  2. Slagzetten volgens MVV-LVA (Most Valuable Victim, Least Valuable Attacker): pion slaat dame eerst, dame slaat pion laatst.
  3. Promoties, vooral naar dame.
  4. Killer moves: rustige zetten die op dezelfde diepte eerder een cutoff gaven.
  5. History heuristic: een teller per (van, naar) die stijgt bij elke cutoff.
  6. De rest.
VALUES = {chess.PAWN: 100, chess.KNIGHT: 320, chess.BISHOP: 330,
          chess.ROOK: 500, chess.QUEEN: 900, chess.KING: 0}

def move_score(board, move, hash_move):
    if move == hash_move:
        return 1_000_000
    if board.is_capture(move):
        victim = board.piece_type_at(move.to_square) or chess.PAWN  # en passant
        attacker = board.piece_type_at(move.from_square)
        return 100_000 + 10 * VALUES[victim] - VALUES[attacker]
    if move.promotion:
        return 90_000
    return history[move.from_square][move.to_square]

def ordered_moves(board, hash_move=None):
    return sorted(board.legal_moves, key=lambda m: move_score(board, m, hash_move), reverse=True)

06 · Iterative deepening en tijd

Altijd een zet klaar hebben

Je weet niet op voorhand hoe diep je binnen de tijd raakt. Iterative deepening zoekt diepte 1, dan 2, dan 3, … tot de tijd op is, en speelt de beste zet van de laatste volledig afgewerkte diepte.

  • Het lijkt verspilling, maar de ondiepe zoektochten kosten weinig. De laatste diepte domineert, omdat het werk exponentieel groeit.
  • De beste zet van diepte d is de eerste zet die je op diepte d+1 probeert. Dat geeft betere ordering en dus meer cutoffs.
class TimeUp(Exception): ...

def calculate_move(self, board, constraints={}):
    self.deadline = time.time() + self.time_budget(board, constraints)
    best_move = next(iter(board.legal_moves))     # noodzet
    for depth in range(1, 64):
        try:
            best_move = self.search_root(board, depth, best_move)
        except TimeUp:
            break                                 # onafgewerkte diepte negeren
    return best_move

# in negamax, bv. elke 1024 knopen:
#     if time.time() > self.deadline: raise TimeUp
Let op bij een exceptionAls je midden in de zoektocht een TimeUp gooit, staan er nog push-zetten op het bord. Gebruik try/finally: board.pop() of zoek op een board.copy() aan de wortel. Anders geef je een zet terug voor een stelling die niet meer klopt.

Tijdsbudget uit de UCI-klok

def time_budget(self, board, c):
    if 'movetime' in c:
        return c['movetime'] / 1000 * 0.95
    remaining = c.get('wtime' if board.turn else 'btime')
    if remaining is None:
        return self.time_limit_move               # bv. 5.0 s uit example_engine
    increment = c.get('winc' if board.turn else 'binc', 0)
    return remaining / 1000 / 30 + increment / 1000 * 0.8

07 · De evaluatiefunctie

EVAL(s): een schatting van wie er wint

Je kan niet tot het einde zoeken, dus aan de rand van de zoekboom schat je de waarde. Een goede EVAL is snel en sterk gecorreleerd met de winkans. Meestal is ze een gewogen lineaire som van features. Waarden worden uitgedrukt in centipionnen (cp): 100 cp = één pion.

FeatureIdeeTypische orde
MateriaalP 100, N 320, B 330, R 500, Q 900dominant
Piece-square tablesBonus per stuk per veld: paard in het centrum, pion die oprukt, koning veilig achter pionnen±10–50 cp
LoperpaarTwee lopers samen zijn meer waard+30–50 cp
PionstructuurStraf voor dubbel- en geïsoleerde pionnen, bonus voor vrijpionnen±10–80 cp
MobiliteitAantal zetten per stuk (duur om te berekenen!)±2–5 cp per zet
KoningsveiligheidPionschild, aanvallers rond de koning±0–100 cp

Tapered evaluation

Een stuk is niet overal evenveel waard. De koning moet in het middenspel verstopt blijven, maar in het eindspel moet hij naar het centrum. Bereken daarom twee scores (middenspel en eindspel) en meng die op basis van een fase die daalt naarmate er stukken van het bord gaan:

phase = min(24, 1*knights + 1*bishops + 2*rooks + 4*queens)   # 24 = beginstelling
score = (mg_score * phase + eg_score * (24 - phase)) / 24

Dit is een voorbeeld van een niet-lineaire evaluatie, zoals les 08 aanhaalt. Bekende tabellen zijn de PeSTO-tabellen. Gebruik je ze, vermeld dan de bron in je rapport.

Snelheid teltElke extra feature kost tijd per knoop, dus minder diepte. Een evaluatie die 2× trager is, moet duidelijk beter spelen om dat verlies goed te maken. Meet het (module 13).
08 · Quiescence search en het horizoneffect

Niet evalueren midden in een slagwisseling

Stop je op diepte 4 net nadat je dame een pion sloeg, dan ziet de evaluatie "+1 pion". Dat de dame op de volgende zet verloren gaat, ligt achter de horizon. Dat is het horizoneffect.

Quiescence search zoekt aan de rand verder, maar alleen naar slagzetten (en eventueel promoties), tot de stelling "rustig" is:

def quiesce(board, alpha, beta):
    stand_pat = evaluate_side_to_move(board)
    if stand_pat >= beta:
        return stand_pat               # al goed genoeg: niet slaan mag ook
    alpha = max(alpha, stand_pat)
    for move in ordered_captures(board):     # MVV-LVA
        board.push(move)
        score = -quiesce(board, -beta, -alpha)
        board.pop()
        if score >= beta:
            return score
        alpha = max(alpha, score)
    return alpha
  • Stand pat: de speler aan zet hoeft niet te slaan. De huidige evaluatie is dus een ondergrens.
  • Sta je schaak, dan geldt stand pat niet: je moet een uitweg zoeken, dus genereer alle zetten.
  • Het horizoneffect verdwijnt hiermee niet helemaal. Les 08 noemt ook singular extensions: een opvallend sterke tak een ply dieper zoeken.
Waarom dit zoveel uitmaaktZonder quiescence hangt een engine stukken op, net zoals de voorbeeld-agent op diepte 1, maar dan steeds op de rand van zijn zoekdiepte. Het is meestal de grootste sprong in speelsterkte na alpha-beta zelf.
09 · Transposition table

Dezelfde stelling niet twee keer doorrekenen

Via verschillende zetvolgordes kom je in dezelfde stelling terecht (e4 e5 Nf3 en Nf3 e5 e4). Dat heet een transpositie. Een transposition table (TT) slaat per stelling het resultaat op.

  • Sleutel: een Zobrist-hash, een 64-bit getal per stelling. In python-chess: chess.polyglot.zobrist_hash(board).
  • Waarde: diepte, score, vlag en beste zet.
VlagWanneerBetekenis van de score
EXACTα < score < βExacte waarde
LOWERBeta-cutoff (score ≥ β)Echte waarde is minstens zo hoog
UPPERGeen zet verbeterde αEchte waarde is hoogstens zo hoog

Een opgeslagen resultaat mag je alleen gebruiken als de opgeslagen diepte ≥ de gevraagde diepte. Ook als dat niet zo is, blijft de opgeslagen beste zet waardevol: probeer hem eerst (module 05).

ValkuilenMat-scores zijn afhankelijk van ply, dus pas ze aan bij opslaan en ophalen. Herhalingen hangen af van de geschiedenis, niet alleen van de stelling. Begrens de grootte van de tabel, anders loopt je geheugen vol.
10 · Opzoeken in plaats van zoeken

Openingsboek en eindspeltabellen

Les 08 noemt dit "search versus lookup": aan het begin en einde van een partij zijn er weinig stellingen, dus je kan ze opzoeken.

  • Openingsboek: chess.polyglot.open_reader("book.bin") geeft gewogen zetten voor bekende openingsstellingen. Kost geen zoektijd en voorkomt rare openingen.
  • Eindspeltabellen (Syzygy): chess.syzygy.open_tablebase(pad) geeft de perfecte uitkomst voor stellingen met weinig stukken. De bestanden zijn groot. Voor 3–5 stukken gaat het om honderden MB.
Wees eerlijk in je rapportEen boek maakt je engine sterker zonder dat jullie AI daarvoor iets doet. Vermeld duidelijk wat uit een boek komt en wat jullie eigen zoekwerk is, en zorg dat de engine ook zonder boek werkt.
11 · Alternatieven: MCTS en RL

Waarom niet Monte-Carlo of reinforcement learning?

MCTS bouwt een boom op met vier stappen per iteratie: selection, expansion, simulation (een playout tot het einde) en back-propagation. Bij selectie kiest het kinderen met UCB1:

UCB1(n) = U(n) / N(n)  +  C · sqrt( ln N(parent) / N(n) )
          exploitation        exploration
  • Sterk bij een zeer hoge branching factor (Go) en als er geen goede evaluatiefunctie bestaat. Het heeft alleen de spelregels nodig.
  • Zwak voor schaak in Python: willekeurige playouts zeggen weinig over een schaakstelling, en één playout van ±80 zetten kost in Python veel tijd. Schaak heeft scherpe tactiek, waarbij één zet alles verandert. Les 08 zegt het ook: MCTS kan zo'n zet missen.

Reinforcement learning (zoals AlphaZero) combineert MCTS met een neuraal netwerk dat de policy en de waarde leert via self-play. Dat vraagt enorme rekenkracht, veel meer dan jullie in drie weken hebben.

Voor de verdedigingJe moet niet alles bouwen, maar je moet je keuze kunnen motiveren. "Alpha-beta, omdat schaak een goede handgemaakte evaluatie toelaat, de branching factor beheersbaar is en tactiek precieze rekenkracht vraagt" is een sterk antwoord.
12 · Snelheid in Python

Meer knopen per seconde = dieper zoeken

Een pure Python-engine op python-chess haalt grofweg enkele duizenden tot een paar tienduizenden knopen per seconde. Elke factor 2 telt.

  • Profileer eerst: python -m cProfile -s cumtime -m scripts.play_self. Optimaliseer pas waar de tijd echt naartoe gaat.
  • Gebruik push/pop, geen board.copy() per knoop.
  • board.is_game_over() is duur. Check alleen wat je nodig hebt, en pas als er geen legale zetten zijn.
  • Maak list(board.legal_moves) één keer per knoop, niet meerdere keren.
  • Lees de stukken via board.pieces_mask of bitboards (board.occupied_co[chess.WHITE]) in plaats van een lus over 64 velden.
  • Een incrementele evaluatie, die bij elke zet bijwerkt in plaats van alles te herberekenen, is sneller maar moeilijker. Doe dat pas als de rest werkt.
13 · Testen en meten

Bewijzen dat een wijziging je engine sterker maakt

  • Tactische testposities: "mat in 1/2" en "win een stuk". Je engine moet ze op een kleine diepte vinden. Dit zijn je unit tests.
  • Versie A tegen versie B: speel veel partijen (≥ 50), wissel de kleuren af en start vanuit verschillende openingen. Eén partij zegt niets.
  • Tegen Stockfish: Skill Level 0–20, of UCI_LimitStrength + UCI_Elo (vanaf ±1320). Zo krijg je een ruwe Elo-schatting.
  • Interne metingen: bereikte diepte per zet, knopen per seconde, aantal cutoffs, TT-hit rate.
